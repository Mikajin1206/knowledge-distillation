# Agent 平台选型验证（2026-10-26）

> **同日修订：**应用户决定，平台定案由下文第 1 节的 Spring AI Alibaba Agent Framework/Graph 1.1.2.2 修订为 **Python LangGraph**——现有代码全部为 Python，切换语言栈成本高；LangGraph 候选已通过本文同一代表性验证（1.2.17），且已在现有依赖与 `ai_generate_solution` 运行代码中使用。本文验证事实保持原样，当前定案以 [06](../06-开源方案候选与评估维度.md) 为准。

## 1. 结论与验收口径

选定 **Spring AI Alibaba Agent Framework / Graph 1.1.2.2** 作为新 Java Agent 服务框架，依赖对齐 Spring Boot 3.5.8 / Spring AI 1.1.2 / MCP Java SDK 0.17.0，部署语言基线 JDK 21。用户明确维护团队以 Java/Spring 为主；Java 候选与 Python 候选均通过代表性本地流程，选择依据为团队维护能力及任务流程适配，没有据短流程做性能排名。

K24 完成范围为：固定版本核对、隔离安装与编译、真实模型 + 合成 MCP 知识流程、脚本确认、正常退出后的跨进程恢复、本地重复恢复检查、现有知识服务空库只读协议验证及适配方案。**正式 Spring Boot 服务、企业微信、生产 checkpoint、真实 RAG 与完整售前方案未实现或验收。** 本次不改变现有知识服务版本，也不恢复 K13/K16，不包含独立公司模型代理项目。

## 3. 合成材料及真实调用

客户、手册、确认输入、事务和方案都明确标记 synthetic。真实模型请求使用已有配置的官方 DeepSeek API、模型别名 `deepseek-flash`；未传真实客户资料，未读 Word、上传、蒸馏、审核、发布或索引。

合成手册为 `synthetic-manual`、revision=1，hash=`31c8978b9a07cf78af0a3bb38aae6629fd34d7ebd3dc464b5f153e9ad58b2658`。检索返回订单变更、供应商确认和采购查询，并要求定向补读 `section_rules`。补读正文只证实“订单变更保留版本；供应商在线确认变更内容；采购查看待确认状态”，明确接口未验证、交期及量化收益未知。

三个流程均完成 search → 精确 material_id/revision/hash 的 `section_rules` 补读，`full_document=false`，没有因生成方案读取全文或检索真实库。以下模型请求数及 usage 仅为各自流程消耗，不构成成本/质量基准；提示词、上下文、输出上限及客户端实现不同。

## 4. Java 首选的实际链路

1. Maven 编译通过，Graph 包含 profile → review → solution。profile 内 ReactAgent 以原生 DeepSeekChatModel + SyncMcpToolCallbackProvider 调用合成 MCP，只开放两个只读工具。
2. profile 完成后在 review 前暂停，FileSystemSaver 保存状态并正常退出；`start-state.txt` 无 approved=true，未执行方案节点。
3. 新进程读取同 thread checkpoint，脚本写入 approved=true，恢复 review/solution，生成短合成方案和固定操作 ID 产物。事件显示 profile 仅执行一次，review/solution 各一次，检索轨迹仅两次调用。
4. 第三个进程重复 resume，未再次执行 profile/review/solution，模型结果和产物未增加。固定操作 ID 文件以 CREATE_NEW 保存；这只证明本地顺序场景的幂等实现，不能推导框架对外部事务天然 exactly-once。
5. 合成方案保留三项证实能力、接口与收益缺口，把汇总查询设计标成待核实，并列采购/信息部门应确认的字段、权限、追溯及接口验证材料。

本次 Graph 只保存短研究摘要与工具参数轨迹。完整证据正文保留在探针模型记录中，**这不是正式证据模型实现**；K17/K15 必须将原始工具结果、来源身份、引用和需求基线独立持久化，再提供给方案节点，不得靠模型摘要替代手册细节。

FileSystemSaver 验证仅覆盖正常进程退出与同机顺序恢复；未测试强杀、事务中断、多 worker、并发确认或 PostgreSQL。确认由脚本输入，未验实际销售确认或企微卡片。

## 5. 现有知识 MCP 只读兼容

三个客户端分别启动真实 `ckp.mcp_server`，`PYTHONPATH` 指向当前 src；`CKP_DATA`、`CKP_OUTPUT` 指向独立空路径。全部发现 **38 个工具**，读取 `distill_stages` 确认知识服务 **1.5.6**，调用 `product_material_list` 返回空列表。没有创建知识数据库或 output，不连接真实 RAG。

此项证明当前工具 schema / STDIO / 预检与空库只读调用兼容。生产 HTTP/远程鉴权、RAG 真实命中和生产文件服务不在此证据内，K16 保持暂停。开发接入仍遵循单一知识 MCP，不另建 Java RAG。

LangGraph 另分别验证 beta `langchain.mcp.MCPAdapter` 与标准 Python MCP SDK。错误 hash 被服务拒绝：beta adapter 的 `.ainvoke(args)` 可返回错误文本而不抛异常；完整 ToolCall 会返回 `ToolMessage.status=error`；标准 SDK `is_error` 保留拒绝状态。正式适配须显式判断错误，不能用“未抛异常”表示知识调用成功。Java 错误路径/超时归一化仍由 K17 实现验证。

## 6. 比较发现与必要缺口

- AgentScope 原生 Agent/MCP/确认链路通过。2.0 的独立 runtime 已整合迁移，不应另套旧 runtime；SOP 为实验性能力且未作为此次闭环验证路径。没有验证可直接使用的稳定企微渠道。
- LangGraph 显式状态与确认恢复通过。新 `langchain.mcp` 仍为 beta，但可直接采用标准 SDK，已验证这一替代路径。中断节点会从头执行，外部写入须业务去重；不需要依赖 LangSmith 托管服务。
- Java Graph + 节点内工具循环通过，维护技术栈与用户团队一致。三个候选都要自行做企微、业务权限、正式数据、产物和任务事务，因此不能把框架功能清单当成底座已完成。
- AgentScope 短方案将“推送”写成能力，超出合成手册；LangGraph 短方案自由生成的引用 ID 曾写成 `synth-manual`。这些结果不能作为正式方案验收。K17/K15 需结构化证据、确定性引用和业务质量验收；本轮不展开 K25 提示词调优。
- Java probe 的 MCP 关闭过程出现子进程终止码 143；既有真实 MCP 调用及结果已完成。最初 exec:java 有 Reactor 线程生命周期提示，探针补充 finally shutdownNow 后完成退出；正式服务生命周期须由 K17 独立设计。
