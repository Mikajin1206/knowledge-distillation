## 2. 知识与业务决策

- 项目知识按全生命周期采集，不按售前问题收缩来源；岗位 Agent 从共享知识按任务抽取。
- 原件、蒸馏草稿、审核、发布、检索是不同阶段；上传不触发蒸馏或入库。现有 Word、项目归属、产品领域、正文路由和图形契约沿用 05，不因 Agent 规划改变。
- 一个知识 MCP 提供原件、蒸馏、审核、发布、RAG、资产和撤回。业务 Agent 是调用知识的应用服务，不另配一套 RAG MCP；独立公司模型项目不进入本项目服务架构。
- 公共项目知识、产品手册资料、销售知识分域。销售画像和商机记录不伪造六阶段、不自动进入公共 RAG。当前销售域 schema、发布和权限适配未实现。
- 检索先命中分节，有缺口才同版定向补读；全文和图形按需，所有精确修订/hash 约束继续适用。应用生成结果不自动回灌。
- 客户事实、行业参考、模型假设、销售确认分开。公司核心服务/团队能力需业务目录和证据，现有产品分类目录不能替代能力目录。
- 首期仅保存售前任务、客户主体、输入来源、画像/需求/方案修订和授权，商机标识可选。客户研究及需求不依赖沟通台账；跨任务销售知识发布/检索后续扩展，画像可以在本任务按精确版本使用。
- 售前方案沿用八部分结构，每章先核心思路再详细展开；旧售前模板只读参考，不沿用其短条目字数上限。按实际 RAG 产品/项目证据写清逐项需求的业务步骤、规则/异常、产品匹配、系统衔接、落地边界和价值机制，细节进正文。后续沟通的目标、对象角色、问题、材料和期望确认结果属于首期方案；持续销售跟进管理仍后置。
- 周报从确认的沟通、阶段和行动记录汇总。消息条数、模型请求次数和实际客户沟通次数分开；报告注明已记录数据的覆盖范围。
- 本项目运行记录只覆盖自身业务任务、工具/证据、确认和产物，不承担全公司或个人客户端对话管理。

## 5. 收尾检查

1. 所有新增任务有看板编号，子项状态真实，前置关系明确；原暂停项只在用户明确恢复时变更。
2. 产品与开发文档没有把“依赖存在、设计完成、代码可运行”写成业务已验收。
3. 变更接口能回链当前代码；规划接口清楚标注，不伪装成现有 MCP/HTTP 路由。
4. 文档链接有效、术语/模块/编号一致，历史证据保留原日期、版本和编号。
5. 客户资料、运行数据库、令牌和生成的业务文件不进入公开文档；临时生成/检查文件只放 `tmp/`。
6. 交付说明列实际检查、未验证范围及下一阶段；文档检查不替代真实系统验收。

该规则是项目长期协作约定，不创建自动化任务，也不意味着系统能无人维护地自动修改文档。后续每次迭代由执行者在同一交付中完成同步。
