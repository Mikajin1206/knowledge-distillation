# Agent 平台候选、兼容验证与选型定案

更新日期：2026-10-26。本文对应第一阶段 K24；已完成固定版本的本地最小兼容验证并确定平台，定案同日由 Spring AI Alibaba（Java）修订为 Python LangGraph（见第 2 节）。企微、生产数据库和正式售前业务尚未实现或验收。原网关候选资料已冻结为历史，公司模型代理不属于本项目。

## 1. 第一阶段目标与顺序

当前主线为 **明确 Agent 平台选型 → 建设最小公共底座 → 开发售前 Agent 首个功能闭环**。优先复用开源平台，先围绕同一个企微售前流程比较和验证，再确定一个平台及版本；选型不是只列候选，也不以依赖清单已有某库视为采用。

首个场景为企业微信接收客户资料，调用既有知识 MCP，形成画像与需求讨论，再基于实际产品手册/案例证据详细生成售前方案和销售推进建议，支持销售修订。销售记录/跟进等后续业务及应用优化不扩充本轮选型验证范围。

## 2. 平台定案与候选比较

**定案（2026-10-26 同日修订）：新 Agent 服务采用 Python LangGraph。** StateGraph 管理研究、确认和方案节点，节点内模型/工具循环由 LangGraph/langchain 承担，模型走 OpenAI 兼容 API，MCP 用 Python 标准 SDK；不引入 Admin、Dify 或独立托管 Agent 平台。原同日定案为 Java / Spring Boot + Spring AI Alibaba Agent Framework/Graph 1.1.2.2，应用户决定作废：现有代码全部为 Python，切换语言栈成本高；该考虑优先于维护团队的 Java/Spring 语言偏好。

固定依赖基线：探针验证组合为 LangGraph 1.2.17、LangChain 1.4.7、langgraph-checkpoint 4.3.0、SQLite saver 3.1.2（Python 3.12，MIT）。现有锁文件为 langchain 1.2.10 / langgraph 1.0.10（`ai_generate_solution` 已在用）；K17 新增使用 1.0.10 的 macOS ARM64 独立依赖锁文件并完成本机离线验证，正式跨平台及 PostgreSQL saver 尚待固定与验收；升级须回归现有服务。模型经 langchain-openai 的 OpenAI 兼容接口调用获准国产 API（DeepSeek 既有用法）；MCP 用 Python 标准 `mcp` SDK（requirements-mcp 已含；LangGraph MCPAdapter 仍为 beta，不作依据）。原 Java 组合（Spring Boot 3.5.8 / Spring AI 1.1.2 / MCP Java SDK 0.17.0 / JDK 21）随定案作废，仅作历史。现有 Python 3.12 知识服务及依赖保持不变。

三者都通过了代表性本地验证。先按用户确认的 Java/Spring 维护团队选择 Java 候选；同日用户改判为现有 Python 代码复用优先，据此在两个已通过验证的 Python 候选中选定已在现有依赖与运行代码中使用的 LangGraph，AgentScope 需引入新框架故未选。没有依据把此次短流程的 tokens 或耗时当作性能排名。具体结果见[选型验证记录](验收记录/2026-10-26-Agent平台选型验证.md)。

| 候选 | 比较重点 | 项目边界 |
| --- | --- | --- |
| [LangGraph](https://docs.langchain.com/oss/python/langgraph/overview)（**已选定**） | 状态流程、持久化/恢复、interrupt 人工确认、模型/工具适配与应用服务组织；评估企微适配的自有工作量 | 已在现有依赖清单与 `ai_generate_solution` 运行代码中使用；正式业务对象仍由领域服务管理 |
| [AgentScope](https://github.com/agentscope-ai/agentscope) 2.x | 工具/MCP、状态与记忆、人工确认、服务运行和自定义 IM 适配能力；验证企业微信实际接入路径 | 通过同一验证的 Python 对照候选；未选以避免引入新框架。不用内置 RAG 取代本项目单一知识 MCP；框架记忆不能替代业务事实与版本 |
| [Spring AI Alibaba](https://github.com/alibaba/spring-ai-alibaba) Agent Framework / Graph（定案作废） | Java/Spring 团队维护适配、Spring AI 模型/MCP、Graph 持久状态与确认恢复；固定稳定 tag 验证，不能混用 2.x 预发布 API | 2026-10-26 原定案，同日因现有代码全部为 Python 作废；验证记录保留作历史 |

Dify 和通用拖拽工作流编辑器不在当前架构范围。既有 Python 知识 MCP 保留，不要求迁移语言；首期只实现已选 Python LangGraph Agent 服务，AgentScope 与 Java 候选保留为比较依据和历史记录。

## 3. 同一代表性流程的兼容验证

| 维度 | 必须给出的证据或边界 |
| --- | --- |
| 企业微信入口 | 智能机器人接入方式、可信发送人、单聊/基础群 @ 路由、消息重试、任务状态和产物入口；真实租户可用能力另实测 |
| 现有知识 MCP | 能调用项目/产品检索与精确分节读取，保留来源、版本/hash、失败状态；遵循同版定向补读和按需图形规则 |
| 国产模型调用 | 所选 API/模型版本的工具调用、结构化结果、必要流式/超时及错误能用于该任务；密钥仅通过配置引用 |
| 任务与确认 | 同客户不同任务隔离，画像/需求/方案修订可追溯，人工补充后可继续，旧确认不覆盖新修订 |
| 持久化与恢复 | 重启/失败恢复后任务可继续，恢复重查权限和对象版本，外部写入和结果发送不重复 |
| 工程与维护 | 现有 Python 栈维护适配、知识服务同栈复用、固定版本、领域服务边界、部署复杂度、许可与维护成本；明确需要自有适配的缺口 |

K24.1 完成比较和适配方案，K24.4 完成最小兼容验证并记录定案；它们是开发任务，不可仅以候选文档齐全标完成。需要真实企微/模型凭据的验证在获准配置下实施，模拟与真实结果分别注明。

选型产物至少包括一个确定的平台及版本、选择依据、代表性流程的实际结果、未验证/不支持范围，以及 K17 所需适配清单。验证失败应说明缺口是否阻塞首个场景，再依据证据定案，不能直接宣称兼容。

## 4. 最小公共底座与自有业务边界

K17 基于已定平台，先建设渠道无关的可信身份和任务权限、任务/状态/确认与恢复、现有知识证据适配、持久 worker/outbox、最小国产模型 API 调用以及产物保存。首期不先建设通用多岗位管理平台。

客户主体、来源、画像修订、需求基线、能力目录引用和方案修订属于本项目领域数据；正式商机、销售活动、跟进提醒、周报与跨任务销售知识管理后续扩展。框架状态与业务数据职责分开，公共项目知识仍按全生命周期采集，生成方案不自动回灌公共库。

公司模型代理、员工模型授权、配额用量、个人客户端模型准入和公司对话管理已作为独立项目移出，不计入候选比较、底座建设或售前闭环的前置。模型凭据也不授予知识、客户或仓库权限。

## 5. 与最后统一优化类别的关系

第一阶段验证来源与版本正确、工具可用、任务可恢复、详细方案可供销售使用；必要修复随原任务完成。K14 的专门检索基线与 RAG 调优、K25 的提示词/工作流/质量/时延/成本优化统一留到最后优化类别，不与本轮选型及开发并行，不作为平台定案的额外研究项目。

具体任务和状态仅维护于[产品迭代看板](产品迭代看板.md)，本文只定义选型与适配要求。

## 6. K17 必须补齐的实现

1. Python（FastAPI/既有服务形态）渠道无关应用入口与可信身份、任务入口、确认和产物返回；企业微信租户接入作为所有 Agent 最后的统一任务，当前不做，届时验证长连接/单聊/群 @。
2. 正式任务及修订模型、带版本的确认令牌、过期确认拒绝、权限重查、持久 worker/outbox；框架 checkpoint 与领域事务分别设计。
3. PostgreSQL checkpoint 方案（langgraph-checkpoint-postgres）及业务 schema。此次 SqliteSaver 只用于本地顺序进程恢复；不得直接认作多 worker 生产方案。
4. 现有锁文件（langgraph 1.0.10）与探针版本（1.2.17）对齐固定，并回归 `ai_generate_solution` 现有服务。
5. 单知识 MCP Python 适配（标准 `mcp` SDK）：工具白名单、结构化结果/错误归一化、精确 ID/revision/hash/section 引用和同版补读；生产 STDIO/HTTP 部署方式另按实际边界验证，K16 保持暂停。
6. 最小国产模型适配、限次/超时、失败分类及产物版本保存。Python 侧经 OpenAI 兼容接口调用 DeepSeek（既有 ChatOpenAI 用法，验证流程显式禁用 thinking）；若正式流程要求显式模式或 reasoning 往返，须实现适配并验证。
7. K15 将完整证据正文与引用身份作为独立结构保存，引用标识由服务渲染；不得仅传检索参数或让模型自由生成来源 ID。按真实手册完成详细方案、修订及销售人工验收。

以上实现状态只在看板维护。本次隔离探针不进入正式运行代码；版本对齐与锁文件更新在 K17 实施并回归现有服务。
