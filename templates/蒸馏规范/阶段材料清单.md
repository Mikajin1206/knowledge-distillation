# 阶段材料清单

阶段允许配置和跨阶段关联材料；缺失材料记录缺口，不因缺少某类文件自动认定项目不合格。合同、方案、报告优先作为来源，但不按文件类型直接认定内容正确。

本蒸馏流程只读取 `.docx` / `.doc`。Excel、PPT、PDF、独立图片等非 Word 原件保留在文件库，不作为本任务材料；如用户混选，先按 MCP 拒绝信息停止并询问是否只用 Word 继续。

| 阶段 | 知识范围 | 典型材料 |
|---|---|---|
| 立项与范围 | 项目背景、目标、合同范围、交付边界、约束 | 立项报告、合同/任务书、招投标文件、范围说明书 |
| 调研与需求 | 现状流程、角色、需求、业务规则、需求确认 | 调研纪要、需求规格书、需求确认单、业务规则清单 |
| 方案与设计 | 业务流程、架构、功能、接口、数据关系、设计取舍 | 蓝图/方案设计、架构文档、接口文档、数据字典 |
| 实施与变更 | 配置、迁移、集成、操作步骤、变更原因、问题解决 | 配置清单、操作手册、变更单、问题记录、部署记录 |
| 测试与验收 | 测试场景、缺陷修复、验收结论、实际交付范围 | 测试计划/报告、缺陷清单、UAT 记录、验收报告 |
| 运维与改进 | 环境版本、故障现象、诊断、根因、处置、验证、改进 | 值班/故障记录、诊断报告、处置方案、优化总结 |

## 选材方法

1. 先确认任务材料都是 Word 文件，再看文件名和内容与当前阶段知识范围的对应关系。
2. 合同、方案、报告类材料优先精读；同类多份时先比对新版本或标注版本差异。
3. 关键结论逐条回到材料原文定位；找不到出处的结论不写，或标"待确认"。
4. 材料不够时：在"冲突、缺口与待确认项"章节写明缺什么、影响哪些结论、建议由谁补充；同时用 `distill gap` 登记到任务。
