# 质量检查单

生成草稿时一次自查并评分。评分低或材料不完整不阻止草稿导出；结构和哈希检查不等于语义正确，项目经理仍需复核。

## 机械项（程序强制）

- [ ] 尽量提供来源映射、冲突缺口与待确认项、处理记录；缺项如实记录并计入评分，不阻止导出。
- [ ] sources.json 中每条来源都是任务已关联材料的已关联版本（file_id + version_id 一致）。
- [ ] 优先给出章节/页码/表/图等具体来源位置；未细分时可由服务端补全全文范围并降低追溯评分。

## 内容项（自查）

- [ ] 没有编造：所有数值、结论、成效都能在来源或人工补充中找到依据。
- [ ] 数值带单位、口径、时间和出处；表格计数逐行清点，合计=分项之和，摘要/正文/supports 三处一致（v0.3）。
- [ ] 跨表数字未直接相加或去重当独立案例数；分母范围与表头位置核对过（v0.3）。
- [ ] 关键结论标注事实状态（约定/设计目标/实际实施/验收确认/人工经验/模型推断）。
- [ ] 逐句对照重要状态词（签署、生效、验收、唯一、必须、原因、提升）：每个判断能指出来源原文，或改标"未见证据/待确认"，或单列为模型建议。
- [ ] 没有把"材料未提及"写成否定事实——材料的沉默不是否定；未查看的附件如实标"未核"，未从局部读取推全文件不存在（v0.3）。
- [ ] 原文理由与模型归纳逐句分离；材料记载 A 不等于可推断 A 的代价/动机/唯一性（v0.3）。
- [ ] 冲突清单经过五要素对齐（对象/范围/时间阶段/单位口径/证据等级）；未把阶段演进、范围包含、不同状态判为冲突（v0.3）。
- [ ] 正文外部事实全部能追到已登记来源或可解析的 knowledge_id+revision 链；处理记录含每份材料的三态读取覆盖（已读文本未见/未查看附件/不可读）（v0.3）。
- [ ] 关键流程图尽量还原；看不清或未复原时标待确认并降低图片处理评分，不猜测、不阻断草稿。
- [ ] 模型推断单独标注，未与已验证事实混写；"模型整体整理"的声明不替代逐条标注。
- [ ] 材料冲突已并列记录，未静默裁决。
- [ ] 人工补充标注提供人与时间，未伪装成原件内容。
- [ ] 图像/流程描述有来源定位，不确定项已标注，未把整理建议写成忠实复原。
- [ ] 每份 Word 材料已通过 `distill_word_content` 读取至 `has_more=false`；只处理核心正文相关图片和关键表格。
- [ ] 已先确定核心正文起点；封面、目录、使用对象/阅读说明、版本修订记录、术语/符号图例及其中的图片/表格未写入知识，也未为其调用视觉工具。
- [ ] 按任务评分配置给模型评估的维度打 0–5 分，并给出简短证据和未解决事项；权重版本以任务快照为准。
- [ ] 非 Word 文件已停止处理；混合选择时已先向用户确认是否仅用 Word 继续。
- [ ] 质量不足、未执行的步骤、未确认的事项明确标注；一次生成后提交，不为提高评分反复重提。
- [ ] 保留必要细节（步骤、参数、配置），未为凑篇幅压缩到不可执行。

## 处理记录

正文的"处理记录"章节如实写：使用的材料版本、规范版本、执行的模型、每份材料的读取覆盖三态、检查结果、未完成项。
