版本：4.1

## 1. 看板规则

- 本文件是本项目**唯一的开发任务看板**，也是持续维护的产品迭代记录。所有新增需求、优化项、子任务、进度和状态都统一登记在此。
- [01](01-需求规格.md) 记录总产品基线，[02](02-总体架构与开发文档.md) 记录总体技术与开发设计，[03](03-业务Agent产品与开发方案.md) 记录四类岗位 Agent，[04](04-公司模型代理与对话管理方案.md) 记录国产模型代理，[05](05-上传蒸馏与MD产出交接文档.md) 记录当前知识实现契约，[07](07-单MCP本地RAG开发与黑盒验收.md) 记录验收依据；它们不另设看板。每次迭代按[项目记忆](项目记忆.md)同步产品、开发、状态与证据。
- 看板只维护任务、优先级、状态和当前进度，不记录测试证据、日志、哈希、文件清单或详细验收过程。
- 任务状态按实际阶段更新：需求讨论、待开发、进行中、待验收、已完成、暂停。父任务状态不得掩盖子任务状态。
- 子任务完成后只更新对应子任务和父任务汇总；新增待办先登记，再开始实现。
- 任务按主题归类，前置关系决定实际开发顺序；已有 K01–K16 引用保持稳定，新范围追加编号。历史记录保留当时编号，当前编号以本表和编号映射为准。规划完成不得直接标为应用已实现；用户暂停项不因新增架构设计自动恢复。

状态含义：需求讨论=范围或验收方式仍待讨论；待开发=范围已明确、尚未开始实现；进行中=正在实现；待验收=实现阶段已完成、验收未完成；已完成=当前约定范围已交付；暂停=明确暂缓。

## 2. 当前进度

**当前进度：**现有知识 MCP 为 1.5.6，K01–K11 只在既有本地/真实客户端约定范围已完成；业务 Agent 尚未实现；K24 已完成本地最小兼容验证，2026-10-26 修订定案为 Python LangGraph（现有代码全部为 Python，切换语言栈成本高，原 Java/Spring AI Alibaba 定案作废）。当前第一阶段主线仅为：**K24 明确 Agent 平台选型 → K17 公共底座建设 → K15 售前 Agent 首个功能闭环**。K17 进行中、K15 待开发；真实模型调用与真实知识库检索成功链路已打通，正式服务与生产验证未完成，平台探针不计作公共底座或售前应用实现。2026-10-29 起企微租户接入移至所有 Agent 最后的统一任务 K17.5/K15.9，当前不做；先通过本地或隔离入口完成非企微业务开发与验收。

**后续范围：**销售记录/跟进等业务扩展、其他岗位 Agent 和文件类型扩展后续安排；K13 PDF 与 K16 公司生产适配继续暂停。K14 应用 RAG 调优与 K25 其他 Agent 应用优化归入最后的统一优化类别，单独排期，不与第一阶段开发并行。

**项目边界：**公司模型代理、员工模型授权、配额用量和公司对话管理为独立项目，已移出本项目任务与依赖。业务 Agent 仅保留调用获准国产模型 API 所需的最小适配。历史 K21/K22、K24.2/K24.3 不再作为本项目活动任务，原设计留作历史追溯，不视为已交付或在本项目继续开发。

**验收与优化：**第一阶段仍验证知识来源、版本、画像/需求/方案正确性和真实场景可用性；调参、提质降本与性能优化集中后置。多人生产仍以 K16 对应能力实际完成为前提，任务暂停决定不变。

## 5. 已确认的产品规则

- WorkBuddy 部署保持**一个 MCP 服务、多个工具**；原件、蒸馏、审核、入库、检索、读取、资产和撤回能力归入同一服务。
- 生命周期档案按《阶段材料清单》的六阶段分类。产品资料是独立逻辑资料库，不要求归属客户项目，也不套用项目档案的生命周期要求；规划分类为“产品手册”（第七类）和“培训资料”（第八类），但当前版本只接收规范 Word 产品手册，培训资料入库请求必须拒绝并转入 K12 后续讨论。产品手册记录单选 `products` 和所选产品关联的 `domain`，取值由项目经理从目录中确认；每份产品手册对应一个产品。保留原件并直接解析切片，不做知识蒸馏。产品问题优先检索产品资料；项目实施问题检索项目档案；售前问题根据意图按需联合检索，并区分产品规范与项目实践的来源属性。K10 已在单 MCP 和现有 MongoDB/Milvus 开发环境完成独立逻辑路由；生产资源权限与存储迁移仍归 K16，不要求为产品资料新配独立 MCP 或 Milvus 部署。
- 知识事实进入正文，来源和处理过程留在 sidecar/服务记录；章节只使用 `body` 或 `exclude`。
- RAG 默认先使用检索命中分节。需要补上下文时读取同一知识修订的相关章节；全文只用于整体理解、跨章节关系/冲突或定向补读仍不足的场景。
- 完整图形作为受保护资产保存，不进入普通检索切片；仅在回答需要图形细节时，按命中章节中的精确资产引用读取。
- 草稿、审核、发布、检索和生产部署是不同状态；本地开发能力不等于公司生产服务已接通。
- 第一阶段平台已通过本地最小兼容验证，2026-10-26 修订选定 Python LangGraph（现有代码全部为 Python，原 Java/Spring AI Alibaba 定案作废）；随后建设 Python 最小底座和售前闭环，保留 Python 单知识 MCP。销售事实和权限由本项目业务服务管理，销售知识独立，不自动回灌公共库。
- 公司模型代理及其员工授权、配额用量和公司对话管理属于独立项目，不是本项目范围或开发前置。Agent 保留最小模型 API 调用适配，模型凭据不授予知识资源权限。
- 第一阶段以本地或隔离入口完成知识、画像、需求和详细方案的业务验收；企微租户及客户端验收在所有 Agent 的最后统一进行；RAG 及其他 Agent 应用调优统一归最后优化类别，后续业务功能单独排期。
- 产品、开发、看板与验收范围每次迭代同步；项目记忆和 AGENTS 保存此约定，不新建看板。
